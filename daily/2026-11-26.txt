>> Or this could be a separate command or set of commands. Maybe
>> a keymap. repeat-mode wouldn't help, though, if I understand your usage:
>> any intervening commands would break out of it. So some prefix seems
>> inevitable. Unless we add a command (e.g. a mode) that switches to this way
>> of operation until the mode is disabled.
> This reminds me parallel sequences of visiting locations by next-error.

Reminiscent yes, but at a given time we only need to refer to one 
previous location.

> Would be nice to try avoiding such complexity in this case.
> Maybe it would be sufficient to define the global variable
> for the last used backend?

I'm not sure it would help. We could have a variable for "last used 
buffer and position", but that pair is fetchable from history, as we can 
see.

The backend alone wouldn't help since its methods often depend on the 
right buffer being current (with its minor modes and local variables). 
The buffer position, while often less important, can at least in theory 
affect the behavior too.

So we seem stuck with wrapping 'xref--with-origin-buffer' in all places 
where this behavior is needed.

Or I suppose we could have return a very special backend that does 
backward navigation and then delegates all its methods to "real" 
backend. I haven't prototyped that yet, could be caveats.
