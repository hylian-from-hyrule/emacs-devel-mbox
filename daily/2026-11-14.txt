More important than the name of the package is what it contains and what
that implies about its further development.

Please correct me if I'm mistaken, but it seems that further
maintenance of vibe-spell will require running the same LLM on future
versions of hunspell, to generate new versions of the code in
vibe-spell.  Not just once, not just five times, but over and over.

That LLM is a SaaSS dis-service, right?

It might turn out ok to use source code that was (past tense)
generated by an LLM.  (Our interim policy is to refuse.)  But we
certainly can't have Emacs virtually include, or suggest using, a
program whose maintenance depends on repeatedly updating its source
code by running a nonfree or SaaSS LLM again and again.  Emacs
development would be lastingly dependent on that LLM.

In that scenario, we can't rationally assert that the use of that tool
was done by someone else in the past and we are not morally
responsible for it.  We must reject that kind of dependence by
rejecting vibe-spell.

Some of the changes you suggest are more substantial than mere comments.
That shows we need to resolve the question of how vibe-spell relates
to hunspell.  We've considered two paths:

1. vibe-spell is treated as a form of hunspell, and we intend
to transpose (all, or many) future hunspell changes into vibe-spell.

  a. That will sometimes be done using an LLM.

  b. That will always be done by a human.

2. vibe-spell is an independent program now, and its future development
will not be tied to that of hunspell, though one might get inspiration
from new hunspell features.

There could also be a path 1.5 which is a "sometimes 1 and sometimes
2", but it would raise the same issues as path 1, so we don't need to
treat it separately.

This is the fundamental moral decision we know of regarding vibe-spell.
Path 1a (or 1.5a) is unacceptable since it would tie future development
to a tool it is against our principles to use or recommend.

We could choose path 1b, or path 2, but will people actually follow
that decision, or would we be fooling ourselves?  I think that only
with some time can we tell the answer.  We need enough time for their
to be substantial changes in hunspell that people want to transpose
into vibe-spell.

Aside from this moral issue, there is also the legal issue of whether
this code can be copyrighted (and, therefore, copylefted).  We are
trying to find out, but having an answer may take time.

We must take the time needed for a good final decision.
We must wait and see.

Therefore, don't install vibe-spell now into NonGNU ELPA (or into GNU
ELPA).

When enough months have gone by to give us a basis for a thoughtful
decision, we should consider this question based on what we have seen.

People who force others to work as slaves deserve punishment.  In most
real countries, that is a crime and they can be punished by law.

If they used forced labor in a business, for profit, we can punish
them in a practical way by boycotting the business, and thus denying

campaign to reject that beneficial thing would hurt only the innocent
public.  There is no sense in that.  We should rather campaign to
properly punish the guilty ones.
