There are many package names (and older file names from before we
called them packages) that mean nothing to users, or that users will
find hard to remember.  Often they spread into command names, too.

For instance, the command to put a mime attachment into an email is in
the file `mml.el' and its name is M-x mml-attach-file.  attach-file is
the natural name for this command, but sometimes I have to strain to
recall the prefix, `mml'.  The file's comments suggest that "MML"
means something related to mime, but I can't find why those three letters.

The command to list the GPG public keys I have is `epa-list-keys'
because it is in a file named `epa.el'.  Sometimes I have to strain to
recall the prefix, "epa".  It is an acronym for Easy PGP Assistant,
which could help me remember it, but not reliably.

Over the decades, lots of Lisp files installed with names that were
not chosen to be helpful to users add up to a major obstacle for using Emacs.

It seems to me that we should try to avoid adding to this obstacle.
To have a standard practice of choosing new, helpful names for packages
when we add them is a natural way to do this.

In other words, keeping the old name is not a good default policy
if we want to help the users.

its own training, and each new one costs more than the last. Waiting a
