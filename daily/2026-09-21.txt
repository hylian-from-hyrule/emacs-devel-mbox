Hello,

I would like to propose nightpanel-theme for inclusion in NonGNU ELPA.

Repository:
https://www.google.com/url?q=https://github.com/gregfelice/nightpanel-theme&source=gmail&ust=1790002966110000&sa=E

nightpanel is a dark theme modelled on a Saab instrument cluster seen at
night. The canvas is pure black, body text is an instrument-scale
green, and amber is reserved for the things that would be a needle or a
warning lamp on a real dashboard: search matches, strings, constants,
TODO keywords. Red appears only for genuine errors. Comments and
inactive chrome recede to a dim green, so the code itself is the
brightest thing on screen.

License: GPL-3.0-or-later, notice in the file header
Contents: one file, nightpanel-theme.el, 155 lines
Requires: Emacs 27.1, no package dependencies
Author: me, and I am the only contributor so far
Version: 0.1.0, tagged v0.1.0 in git

The repository has an .elpaignore that excludes screenshot.png, so the
release tarball carries the theme file, the README and the license.

package-lint, checkdoc, and byte-compilation with
byte-compile-error-on-warn are all clean on Emacs 30.1. I am the author
and maintainer, and I am glad to maintain the NonGNU ELPA version and to
coordinate on any changes you would like.

One disclosure, since it is visible in the file. The header carries an
"Assisted-by: Claude:claude-opus-5" line, which follows the MELPA
convention for this. The palette and the face definitions are my own
work. An AI assistant helped with the packaging around them: the header
block, the license boilerplate, the autoload cookie and the commentary.
I read and checked all of it, and the file is short enough to review in
one sitting. Please tell me if NonGNU ELPA would prefer that line
worded differently or dropped.

The package is also under review for MELPA, in melpa/melpa#10239.

If you would rather have a patch against elpa-packages than add the
entry yourselves, say the word and I will send one.

Thanks for considering it,

Greg Felice

Common Crawl itself is just an aggregated web scraping archive, and the 
legal status of the content within it depends on the individual licenses 
of the original websites; therefore, the entire dataset cannot be simply 
defined as "free" or "non-free.

Its own FAQ and Terms of Use confirm this: it "applies as few 
restrictions as possible" but requires users to respect the terms of use 
of the websites being crawled, and to respect third-party copyrights and 
other rights in the content.

To "respect" other websites' rights is impossible task. Such website 
would consist of proprietary content, commercial platforms, personal 
blogs, some free licenses, public domain, problematic content, all 
kinds, mixture of various websites.

This means that Common Crawl does not own the copyright in this content 
and cannot authorize anybody to use others' copyrighted material.

When some datasets derived from Common Crawl are released, they 
explicitly require that the underlying content still be subject to 
Common Crawl's Terms of Use.

Common Crawl's own Terms of Use place the risk primarily on the user: it 
explicitly states that the data is provided "as is," and users must 
assume all risks associated with using the content, including copyright 
infringement risks, and recommends that users seek legal counsel before 
commercial use.

Nothing free as in freedom in CommonCrawl.

  Comes from Dolma:
  https://aclanthology.org/2024.acl-long.840/
  quote from the paper: "while most datasets … were already permissively

  license)" ← cc by-sa is not permissive.

- arXiv via Red-Pajama is a subselection of common crawl:
  https://github.com/togethercomputer/RedPajama-Data
  arXiv has many different licenses, including copyleft ones:
  https://info.arxiv.org/help/license/index.html
  Common Crawl just grabs data from the web, their latest release notes
  2.17 billion pages (361 TiB of data):
  https://commoncrawl.org/blog/september-2026-crawl-archive-now-available
  and has restrictive Terms-of-Use:
  https://commoncrawl.org/terms-of-use

- OpenWebMath states "The documents in OpenWebMath are sourced from
   forum posts, educational content, reference pages, scientific papers,
   blogs, and more. Most content comes from Q&A forums where users
   discuss how to solve problems."
  They don’t filter by license:
  https://arxiv.org/html/2310.06786v1#S3.SS5
  but they include data from stackexchange, that’s definitely creative
  commons attribution sharealike licensed:
  https://arxiv.org/html/2310.06786v1#S4.T4
  stackexchange: "user contributions licensed under CC BY-SA." (not permissive)

- StarCoder they use for code excludes copyleft code:
  https://arxiv.org/html/2211.15533v1
  They have a quite lax criterion for including files, though:
  "We opt to include a file in the permissive license dataset if at least one the repositories containing
    the file has a permissive license."
  So if any dev mistakenly copied a file into a repo with a lax
  license, it will be included in StarCoder.
  https://arxiv.org/html/2211.15533v1#S3.SS1.SSS0.Px3
  And they then "deduplicate" by removing "similar" files, so if you
  copy a permissively licensed file and then add changes, your changes
  will be treated as permissively licensed, too (which is not how
  copyright law works).

  that there’s still GPL content in there, and they just didn’t know and
  didn’t care to check (that information is just a quick web search away):
  https://arxiv.org/html/2211.15533v1#A2
  https://spdx.org/licenses/Font-exception-2.0.html
