Hello Eli and Björn,

After some discussion with Eli (other Ely, sorry for misflyspelling it), 
and Arne, I can just completely agree that right now there is no LLM 
that could be say to be truly free as by GNU software freedom 
philosophy.  We reviewed majority of them.

They may be published under free licenses, yet they are using underlying 
datasets that are often found not to be free.

So their outputs can generate copyrighted text. There is no provenance.

For some LLM to be free it should be probably trained on fully free 
public domain text, which is public domain and not copyrighted in all 
countries, as what is public domain in one country isn't necessarily in 
the other.

So no free LLMs, Björn said it already so precise.

I am using LLM text generation in such a way that I can with full 
confidence publish a website and be sure that it doesn't have 
copyrighted output. My subjects are very specific, prompts are not 
short, and results so unique, that I have no problems publishing such 
outputs. Yet with different usage patterns users can easily output 
copyrighted text. One cannot even know which license was it as there is 
no provenance, and GNU GPL would be violated that way too. So the only 
way would be to have public domain datasets to train some LLM, and that 
may never be.

In general, user remains responsible for copyrights, as usual. Sharing 
the LLM is free, using it free, software free, generating LLM or 
training it is allowed by many ways (not necessarily morally alright) -- 
and outputs are difficult, they may never be free.

Generally, they will run whatever program you tell them to run,
whether free or not.  That sort of situation doesn't raise a moral
issue in the development of GNU Emacs, because the choice of program
to use comes explicitly, the user.

The sort of decision which we are compelled to make, in the
development of GNU Emacs (or any other program), is whether it will
_implicitly_ lead users such as you to run some nonfree software --
without your making an express decision to run that program.

This moral issues arises in the situations where the choice of program
is not made at the user's own spontaneous initiative.  For instance,
situations where Emacs itself suggests running that program, perhaps
by including it in a menu of suggested answers to some question.

So our policy is that GNU Emacs does not invite the user onto a path
that leads the user to run a nonfree program.  The choices Emacs
suggests to you must not lead to that result.  If a choice would lead
to that result, Emacs must not suggest that choice.

If you specify a choice that GNU Emacs didn't suggest, that's different.
Emacs should not try to control you.

Emacs can suggest loading each of the packages in GNU ELPA and NonGNU
ELPA.  So those packages should not lead the user to run any nonfree
software.  That must be part of the criteria for having any particular
package in our package archives.

If the user, at per own initiative, gives a command to load a package
that Emacs did not suggest, then Emacs obeys.
