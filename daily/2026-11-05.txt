LLMs deserve the same. Not "welcome", not "ban", but review with the same

tmux now supports images, both kitty and sixel images.  If you do this, 
you should also support sixels which are more widely supported.  What 
tmux does when it sees an image is upload it into tmux and hold it as an 
image and on display, output it as either sixel or kitty depending on 
what's supported.  This way, you can have a sixel image displayed on a 
kitty terminal and visa versa, tmux insulates you from the format.

I do not know if this will help you in adding this to emacs if emacs 
handles all the scrolling and clipping.  emacs also puts the tty in 
alternate screen mode so it would not take advantage of tmux's copy 
buffer, so emacs would have to handle all of the scrolling and such.  It 
should be possible.

There are 2 types of kitty images, I think you are thinking of the 
unicode placeholder type where the image is split into cells (character 
shaped blocks) which the local terminal knows which bit of the image to 
put in that space.  What I don't know is what would happen with the 
other type of kitty image which is called the kitty graphics protocol.

I think what you probably need to do is let people open a file 
containing an image, either a sixel or jpg or whatever, then, uses 
whatever image display capability is available in the terminal to 
display them, handling clipping and scrolling.
