Greetings,

I'd like to propose card-games for NonGNU ELPA; the attached patch adds
it to elpa-packages.

card-games is a collection of about thirty card games for Emacs:
solitaires (Klondike, FreeCell, Spider, Canfield, Gaps, ...), trick-taking
games (Hearts, Spades, Bridge, Euchre, 500, ...), the rummy family,
Cribbage, Scopa and others.  Cards are drawn as SVG on a graphical display
and as Unicode text in a terminal; every game plays with the keyboard, and
with the mouse where there is one.  An Info manual is included.  500 can
also be played between Emacs sessions over TCP (localhost unless the user
chooses otherwise).

  Upstream:  https://code.bru.st/corwin/card-game.el  (anonymous https)
  Version:   1.0.93, tagged; requires Emacs 26.1
  License:   GPL-3.0-or-later; the manual is GFDL 1.3-or-later or CC BY 4.0
  Depends:   nothing outside Emacs
  Also on:   MELPA

Before sending I built it locally with elpa-admin from this entry
(make build/card-games, release and devel tarballs) and installed the
result in emacs -Q; the Info manual and its GFDL appendix open.
Byte-compile, checkdoc and package-lint are clean, and the 166 ERT tests
pass.  An .elpaignore keeps tests, hooks and build files out of the
tarball.

I wrote it and maintain it, and I'm happy to keep maintaining it in
NonGNU ELPA. I used Claude (mostly Opus 4.8, recently Opus 5.2) to
refine from a pair of hand-written proofs of concept. Each LLM
supported commit for this package is so marked with an Assisted-by
trailer.

Hi Peter, Emacs,

I would like to propose adding yet another alert package for Org mode[1]
to GNU ELPA.

I have been reading through your package 'org-notify', Peter, which I
was not aware of.  I have been using my own package for this purpose and
it looks like we've diverged quite a lot.  I like that you have spent
more time implementing alternative alert styles, besides dbus
notifications, and added support for Macs and pop-up buffers.  I would
like your help testing porting that to org-yaap and I would love to help
add support for Android.

We have converged a lot too, allowing notification actions to change the
TODO keyword and using an idle timer to calculate appropriate
notifications in the same Emacs process.  I really like your addition of
relative times to update the timestamp, like a snooze button.

Our packages also differ from other external packages[2,3] by not using
the alert[4] interface and instead relying on Emacs internals to send
notifications.  I purposefully avoided adding any dependencies,
especially outside of ELPA, and so I'm saddened to still see it as a
todo item for org-notify development.

These two reasons, using an idle timer and GNU ELPA compatibility, were
why I initially developed an independent implementation five years ago.

I think we have about the same amount of customizability, but your
options are more compact whereas I feel having many shallow options is
better for discoverability.

org-yaap also has the ability to show a persistent notification for
clocking in and out.

As I mentioned, it fully supports Emacs running in Termux on Android,
including notification actions which can modify the TODO keyword or
launch the relevant buffer.

Regarding org-yaap's inclusion in GNU ELPA: I believe these packages
accomplish the same things in different ways, and provide different
features and customization options.  I still think it would be nice to
provide both packages to users, so, please look through the code and let
me know if it's appropriate to add to ELPA.  I have meaning to submit it
for a while.

'Yaap' is a sort-of double entendre, it is an acronym that displays my
dissatisfaction with the existing solutions, but 'yapping' is also
something that little dogs do to get your attention, and so I thought
that was a good metaphor for an alert.

Best,

Amy

[3]: https://github.com/spegoraro/org-alert

[3]: https://github.com/doppelc/org-notifications

[4]: https://github.com/jwiegley/alert
