Jean Louis <bugs@gnu.support> writes:

> A 2026 Avast report found that 52% of adults have shared or considered
> sharing sensitive information with a LLM tool, including CVs and work
> documents.

In other words, 48% of people are responsible and do not engage in that
behavior. I am optimistic that the situation will improve and that the
"wild west days" will eventually come to an end, as people learn. BTW,
many people publish their CVs online for anyone to read, so is it really
such a big deal?

Emacs already offers countless ways to shoot oneself in the foot, but I
still want it to remain a powerful tool for users willing to take full
responsibility for their actions.

> Wikipedia stores and serves published text; it does not compute your
> result for you. This is also why the "hiring a programmer" analogy
> fails: a hired programmer is a person with their own judgment and
> responsibility, not a service that performs your computing under a
> provider's control.

I see no fundamental philosophical difference between hiring a person or
a company to handle programming work and "hiring" an LLM agent to do the
same. In either case, I ask (or "prompt") someone or something else to
perform a task. At that point, I no longer have full control until I
receive the output and can decide whether it meets my requirements.

Obviously, there are numerous considerations - social, ethical,
financial, qualitative, and so on - but if you think this really
carefully solely from the perspective of Computing Freedom, is there
really a difference? Both humans and LLMs (even free/local!) are
nondeterministic, when you hand them a complicated task, you don't know
the outcome exactly beforehand, and neither can be trusted 100% to give
guaranteed results, or keep a secret.

We continue to delegate tasks to these imperfect, nondeterministic
entities because the benefits are substantial, and in some cases, it is
the only viable option.

> Not so largely ephemeral... 😃 OpenAI's documentation confirms it uses
> "information provided or generated by users" as one of three primary
> sources for developing its models.

My point was that the user holds the primary copy of data, unlike in
many "cloud" services like Google Docs or Microsoft O365, that are very
clearly "SaaSS". If you lose access to an LLM service, you can no longer
use it, but you dont lose any the data you already have (unlike what
regulary happens when Google/Apple etc. close accounts). Unless it's a
use case where you rely on constant access to some particular LLM (bad
risk management), you can probably just switch to another provider and
continue working. Or simply fall back to human work.

OpenAI has settings under Data Controls to turn off using your LLM
converstations for training. (Sure, they can lie.) For some type of
data, it actually is a good idea to use it for training.

> "We already know that Copilot as it stands is unacceptable and unjust,
> from our perspective. It requires running software that is not
> free/libre (Visual Studio, or parts of Visual Studio Code), and
> Copilot is Service as a Software Substitute. These are settled
> questions as far as we are concerned."

That is precisely why Hermes seems to be a better (more free)
alternative, and I feel banning hermes.el or other freedom respecting
LLM related packages from ELPA would be counterproductive.

suggests it. Stallman, citing Wiktionary meanings 5 and 7 of "steer":

Package corresponding to the description exists in Emacs:

You can see here:
https://www.gnu.org/software/emacs/manual/html%5Fnode/elisp/Suspicious-Text.html#1

textsec-suspicious-p is an autoloaded Lisp function in
‘textsec-check.el’.

(textsec-suspicious-p OBJECT TYPE)

Say whether OBJECT is suspicious for use as TYPE.
If OBJECT is suspicious, return a string explaining the reason
for considering it suspicious, otherwise return nil.

Available values of TYPE and corresponding OBJECTs are:

  ‘url’                   -- a URL; OBJECT should be a URL string.

  ‘link’                 -- an HTML link; OBJECT should be a cons cell
                            of the form (URL . LINK-TEXT).

  ‘domain’               -- a Web domain; OBJECT should be a string.

  ‘local-address’        -- the local part of an email address; OBJECT
                            should be a string.
  ‘name’                 -- the "display name" part of an email address;
                            OBJECT should be a string.

  ‘email-address’        -- a full email address; OBJECT should be a 
string.

  ‘email-address-header’ -- a raw email address header in RFC 2822 
format;
                            OBJECT should be a string.

If the user option ‘textsec-check’ is nil, these checks are
disabled, and this function always returns nil.

   Probably introduced at or before Emacs version 29.1.
