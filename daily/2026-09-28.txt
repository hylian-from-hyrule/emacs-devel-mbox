That is not acknowledgment. The GNU Coding Standards distinguish between

"you should give only the necessary information to help those who

give, or refer to, any further information about the proprietary program

The package violates both clauses of that rule. It gives further

After the review, the healthy debate had certain warnings by RMS and 
references to GNU coding standards, and so far there was no conclusion 
to accept the package, there was health debate and there was no 
acceptance of the package, or any checklist or any kind of practical 
review of what the package does and if it does pass the GNU coding

Andrew, the August 2023 decision was conditional on the package applying 
a criterion per-LLM, with a SaaSS-specific warning that refers to the 
essay and does not point to the terms of service. The package now has 
seven SaaSS modules, each named after the service, and the warning 
function returns the terms-of-service URL, which is the opposite of what 
Stallman asked for in August 2023. So this is not a re-litigation — it 
is a report that the conditions of the original decision are not being 
met.

Here are the criteria Stallman set in August 2023, with the reason for 
each:

1. All LLMs are unjust.
-----------------------

Stallman wrote: "All the large language models are unjust — either the 
models are nonfree software, released under a license that denies 
freedom 0, or they are not released at all, only made available for use 
as SaaSS."

There is no such thing, in Stallman's analysis, as a neutral LLM. Every 
one is either non-free software or SaaSS.

I was hoping there is one free LLM, and after Ellie's input, I found 
none. I wish there would be, yet there is none.

2. Well-known LLMs may be mentioned; obscure ones must not.
------------------------------------------------------------

Stallman wrote: "If a language model is much better known than GNU 
Emacs, it is ok to have code in Emacs to make it more convenient to use 
Emacs along with the language model. If the language model is not so 
well known, then Emacs should not mention it in any way."

And in that statement by RMS I am very sure he knows what is he talking 
about. He did not talk of SaaSS but he talked about the actual LLM, as 
data, saved as file, with which one can do inference.

The "well-known" exception exists because users already know about the 
well-known ones. Mentioning an obscure one would tend to popularize it 
more than it would popularize Emacs.

3. Commands that support them must warn the user, every user.
--------------------------------------------------------------

Stallman wrote: "If Emacs is to have commands specifically to support 
them, we should make those commands inform the user — every user of each 
of those commands — of how they mistreat the user."

The user must be told what the command does to them. A warning that is 
easy to miss is not a warning.

4. Server-based LLMs are SaaSS, and SaaSS is always unjust.
-----------------------------------------------------------

Stallman wrote: "As for LLMs that run on servers, they are a different 
issue entirely. They are all SaaSS (Service as a Software Substitute), 
and SaaSS is always unjust."

The SaaSS analysis is separate from the non-free-software analysis. A 
server-based LLM is not just non-free software; it is a service that 
performs the user's computing on someone else's machine.

Your packages:

llm-azure.el — connects to azure.microsoft.com
llm-claude.el — connects to api.anthropic.com
llm-deepseek.el — connects to api.deepseek.com
llm-gemini.el — connects to generativelanguage.googleapis.com
llm-github.el — connects to models.inference.ai.azure.com
llm-openai.el — connects to api.openai.com
llm-vertex.el — connects to aiplatform.googleapis.com

directly contradict the above statement by RMS from that very same 
healthy debate. What is the point of the debate if the GNU coding 
standard is not followed?

What is point of asking people to review the package when nobody reviews 
it against a known standard?!

5. The warning for SaaSS must refer to the essay, and must not point to 
the terms of service.
---------------------------------------------------------------------------------------------

Stallman wrote: "I think that it is better to present the URL of the web 
site's front page rather than the terms of service themselves. If we 
point the user at the terms of service, we are directly helping the 
company impose them."

Pointing the user at the terms of service helps the company impose them. 
The user should be told that the service is unjust, not directed to the 
document that formalizes the injustice.

Your warning function returns the terms-of-service URL — the exact thing 
Stallman said not to do, because pointing users at the terms of service 
helps the company impose them, rather than telling the user that the 
service is unjust. Is that wrong or right statement? I have installed 
package `llm` and reviewed it and deleted it. I will install it again to 
make review again. Tell me if I am wrong.

6. The warning should mention that terms of service are a second 
injustice.
---------------------------------------------------------------------------

Stallman wrote: "Any restrictions imposed by terms of service could add 
to the bad. Perhaps it would be good to mention that that second 
injustice exists."

SaaSS is one injustice. Terms of service that restrict what the user can 
do are a second, separate injustice. The user should be told about both.

Yet nothing in those statements by RMS ever implied that SaaSS packages 
should be in Emacs ELPA. See above SaaSS related statement.

7. The warning should mention the democratic alternative.
----------------------------------------------------------

Stallman proposed: "If society needs to restrict some of the uses of 
language model systems, it should do so by democratically passing laws 
to penalize those actions — regardless of how they are done — and not by 
allowing companies to impose restrictions arbitrarily on users."

The alternative to corporate terms of service is democratic legislation. 
The warning should say so.

The package as it stands does not meet criteria 4, 5, 6, or 7.

Criterion 4: The package does not distinguish SaaSS from non-free 
software. Its warning function treats them as the same case.

Criterion 5: The warning function returns the terms-of-service URL. That 
is the thing Stallman said not to do.

Criterion 6: The warning does not mention the second injustice of terms 
of service.

Criterion 7: The warning does not mention the democratic alternative.

So the report is not a re-litigation. It is a report that the conditions 
Stallman set in August 2023 have not been implemented, and that the 
package has grown since then — from two SaaSS providers to seven — 
making the gap larger, not smaller.

I appreciate you for all the efforts. This message is not personal, it 
is philosophical. Can you see above what is happening?

You've got an excessively narrow picture of that word.  "Recommend" in

I'm trying to discuss a real problem: ELPA seems to go against the
main GNU Project moral policy -- our commitment to software freedom

alternatives meant submitting to injustice, we would not have
mentioned it.)  We need to be careful when we do that.

the user a set of three choices, and that recommends all three; but at
least one of those choices is something we don't want to encourage
users to do.  (I have not seen a full discussion of the other two;
they might be ok but I don't know that as of now.)

I speak as the Chief GNUisance, addressing the maintainers and
developers of GNU Emacs.

Yes, I will present it in simple way, as details are important:

Here are the components:
========================

1. hermes.el is the Emacs package and now in ELPA. It runs inside Emacs 
on user's computer. It is front-end that provides dashboard and 
functions, like to send prompts and receive responses, to and from the 
server running the LLM and other commands. It does not contain LLM 
itself and does not itself do any inference, the sole job of hermes.el 
is to talk to software named `Hermes Agent`. As a side note, this 
program is generated by the SaaSS as it says so in the git repository 
which is more copyright issue for the FSF to resolve

2. Hermes Agent is the dependency, separate program developed by Nous 
Research company, not by GNU. The Hermes Agent runs on user's computer 
(I believe it could run on network too). It has free software license 
MIT and it is the program that actually talks to network API that serves 
LLM. It handles network requests, the tool dispatch (like running shell 
commands, generating python, executing programs, inspecting code, or 
communicating with user through messengers), it is handling sessions and 
provider configuration. Providers can be SaaSS as large list and main 
purpose of this program is to connect to SaaSS. Provider can also be 
local software running and serving LLM input/output.

3. The LLM servers is the third component. Those are SaaSS remote 
servers. These run on the providers' computers, not on the user's. They 
include Nous Portal, OpenAI, Anthropic, Google, DeepSeek, AWS, Azure, 
and others.  They are the services that perform the actual inference. 
The non-free and locally running LLM software such as LM Studio is 
mentioned as one of options to the user. The locally running LLM server 
could be also one of options for the user.


What happens when the user starts hermes.el
--------------------------------------------

1. The user installs hermes.el from GNU ELPA, or loads it manually.

2. hermes.el does not work without Hermes Agent. Hermes Agent must be 
installed separately. The usual way to install it is to run a shell 
script from the Hermes website:

     curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

3. After installation, the user runs the setup wizard, usually by typing 
hermes setup. The wizard is part of Hermes Agent, and it runs on the 
user's computer.

4. The wizard presents a menu with three options:

     1. Quick Setup (Nous Portal) — marked as "the recommended fast path"
     2. Full Setup — configure every provider yourself
     3. Blank Slate — everything off except the bare minimum

5. The first option is pre-selected, and it is marked "recommended." If 
the user accepts it, the wizard logs them in to Nous Portal and sets 
Nous as their provider. This is the step where the user is invited to 
surrender control of their computing to a server.

6. If the user chooses Full Setup, the wizard presents a long list of 
providers. On the current version, the list has roughly thirty entries: 
Nous Portal, OpenAI, Anthropic, Google, OpenRouter, xAI, GitHub Copilot, 
AWS Bedrock, Azure Foundry, DeepSeek, and many others. Almost all of 
them are remote SaaSS. Only two options are local: LM Studio (being 
non-free software) and actual computer.

7. If the user chooses Blank Slate, the wizard still presents the same 
provider list. Blank Slate reduces what is enabled by default, but the 
user must still choose a provider, and the provider list is the same.

8. Once a provider is chosen, Hermes Agent sends the user's prompts to 
that provider's server. The server performs the inference. The result is 
returned to Hermes Agent, which passes it to hermes.el, which displays 
it in Emacs.


Where each component runs
-------------------------

- hermes.el runs in Emacs, on the user's computer.
- Hermes Agent runs on the user's computer.
- The SaaSS LLM provider runs on the provider's server, which the user 
does not control.

It is possible that user runs LLM on his computer as well. In this case 
there is no free LLM that I know, and there is no fully free software to 
run it, as hardware needs GPU and GPUs from Nvidia, AMD and Intel, all 
of them needs minimally non-free binary blob as firmware. User could run 
fully free some small language models (which models itself is most 
probably not free) on the CPU, though for many that is slow and not 
efficient.

I wish to have fully free solution to run LLMs on computer, that is my 
personal goal. Though I don't have it yet.


What "their servers" means
--------------------------

"their servers" means the servers of the SaaSS providers — Nous 
Research, OpenAI, Anthropic, Google, and so on. These are the computers 
that perform the inference. The user chooses which provider to use, but 
the computing is done on the provider's machine, not on the user's.


The step where the user is invited to surrender control
-------------------------------------------------------

The invitation happens at step 5 above: when the wizard presents Quick 
Setup (Nous Portal) as the recommended option, and the user accepts it. 
 From that point on, the user's prompts are sent to Nous Portal's 
servers, and the inference is performed there.

The same happens with Full Setup and Blank Slate, except that the user 
chooses a different provider. In all three cases, the computing is done 
on a server the user does not control.


Why this is SaaSS
-----------------

The essay on SaaSS 
(https://www.gnu.org/philosophy/who-does-that-server-really-serve.html) 
defines SaaSS as using someone else's service to do computing that you 
could do on your own computer with free software. LLM inference is such 
a computation: it can, in principle, be done locally with a free 
inference engine and a free model. When it is done on a remote server 
instead, that is SaaSS.

Hermes Agent does not run the model locally — and neither does 
hermes.el, which depends on it — so when hermes.el passes a prompt to 
Hermes Agent, Hermes Agent sends it to a remote server, and the server 
performs the inference; that is SaaSS by the definition in the essay.


The link in the package description
-----------------------------------

The package description of hermes.el contains a link to the Hermes Agent 
quickstart page. That page presents Nous Portal as "Easiest path: Nous 
Portal" and "The recommended fast path." So the package description 
points users directly to the page that makes the invitation.

FSF-approved distributions (the ones that are derivatives of other
distributions which do include proprietary software).

The implications of this discussion therefore are much more
wide-reaching than Emacs maintenance.
