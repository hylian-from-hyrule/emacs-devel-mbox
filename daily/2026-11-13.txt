Richard Stallman <rms@gnu.org> writes:

>   > IMO, it's a point to be discussed, hence why I brought it up - if the 
>   > team is collectively OK with that they will have to deal with code 
>   > submission rates growing up at the rates LLMs allow for, then this point 
>   > can be dismissed.
>
> I think these are independent issues:
>
> 1. Will people send us more proposed patches because THEY use LLMs?

This is bound to happen because generating patches with a coding agent
is basically one prompt, if Emacs allows LLM-generated contributions.
For example, to fix a bug, you describe the problem to it and ask for a
patch.  The coding agent will autonomously study the code, change the
code, and validate that the symptom is fixed (not necessarily the root
cause).

I co-maintain an open-source project which does not ban LLM-generated
contributions (only requiring "responsible use"), and I see much more
pull requests nowadays.  I have very mixed feelings because, while some
PRs make perfect sense, many don't.

> 2. Will Emacs get a lot bigger because of OUR installing patches
> made by LLMs?

IME, most LLM-generated patches will be about fixing bugs and improving
performance.  Patches that add features are rare, and they are most
likely rejected anyway because they are usually designed badly and don't
fit into the bigger picture.

positive so as not to lose the contributor, and sometimes do that
off-list.
