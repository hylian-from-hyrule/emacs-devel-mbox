I think there may be a misunderstanding of what "steer" means here. It 
does not mean SaaSS is unavoidable. It means the installation process 
presents SaaSS as the default and easiest path — it asks the user to 
sign up for a SaaSS service during setup, and presents a long list of 
such services as the natural configuration. That is steering, even if a 
conscientious user can deliberately avoid it. If I have misread the 
installer, I would be glad to be corrected on the specifics. But 
repeatedly saying "no, it does not do that" while the evidence suggests 
otherwise is not convincing.

And after my review today, I have found that minuet is in GNU ELPA, and 
it promotes SaaSS directly in its package description.  And I wonder 
about it, as I did read this: Re: [ELPA] New Package: minuet-ai.el:
https://lists.gnu.org/archive/html/emacs-devel/2025-03/msg00770.html#1

So I do not know what was final decision, obviously final decision was 
to include minuet -- yet it directly works with SaaSS.

After a short review today, I find other packages also promote SaaSS:

- minuet is in GNU ELPA, promoting SaaSS directly in its package 
description;
- codex-ide is on NonGNU ELPA, and it directly promotes SaaSS through 
its dependency on the Codex CLI, which defaults to OpenAI's proprietary 
service;
- gptel is on NonGNU ELPA, and its package description begins with 
"Interact with ChatGPT," pointing users first to a proprietary SaaSS 
service (libre LLMs aren't there...);
- aidermacs is on NonGNU ELPA, and it is a front end for Aider, which is 
heavily designed around connecting to remote LLM APIs rather than for 
local computing

What I see is that GNU Emacs packages are now slowly thriving with 
access to SaaSS, and this normalization is happening one accepted 
package at a time.

And the "first leg" theory does not hold up — logically or by common 
sense. If responsibility ends at the first leg, I can evade it by adding 
one more layer: write a free program that accesses a non-free one or 
SaaSS, and the first leg is free. Or provide SaaSS myself, wrapped in a 
free buffer-agent, so no one has to look further. In both cases the user 
is led to the same SaaSS — the maintainers can wash their hands, 
Pilate-style. A rule that is satisfied by one layer of indirection does 
not protect users. It only protects appearances.

-- 
Jean Louis

is that the GNU project sets an example, just as it endorses only fully 
free GNU/Linux distributions (which tend to use Linux-libre kernel). But 
when SaaSS comes through a package dependency, we should not steer users 
toward it. If that example is set wrongly, it reflects badly on free 
software, because instead of helping users do their own computing, we 
steer them to third-party computing. And I am quite sure you would be 
running your own "gpt-alike" on your own machine if hardware prices were 
affordable.

users to use it, is steering users to that site or program.
See Wiktionary:steer, meanings 5 and 7.

That's why the GNU Project has a policy of being careful about
what we refer to -- to make sure we are not influencing users
in a way that encourages using nonfree software (or SaaSS).

This is described in the node References in the GNU Coding Standards.

Our actions must be coherent with our philosophy.

                     Users use or don't use those sites on their own
  > judgment

Each user does apply per own judgment.  But that doesn't mean we have
no responsibility to make sure our suggestions don't encourage the very
practices we aim to change.

             and on their own responsibility.

Users are ultimately responsible for what they do.  But when we suggest
things to users, we are also responsible -- for not making suggestions
that could teach users bad judgment.

That users have the final decision doesn't mean we can be careless in
what we suggest to them.

  > Our recommendation is for using a package, not for accessing sites
  > that package allows.

Using the word "allows" subtly but significantly changes the question
under discussion.  The issue is not which sites the package _allows_,
but which sites it _suggests_.

  >  Should we reject a free Web browser because it
  > allows users to access non-free sites and download non-free software?

This illustrates perfectly how "allows" and "suggests" pose different
questions.  The web browsers in Emacs will allow any web site, but
suggest few sites or none at all.

resistance. There is no evidence that declining to recommend SaaSS will

OpenVINO (Open Source Distribution): The version of OpenVINO on GitHub
