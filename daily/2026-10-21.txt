Sorry for the late reply.

This program is a dumb-ish I/O forwarder, essentially.  You send it JSON
requests like 'send me the contents of this file' or 'run the LSP server to
look up this symbol' or 'run this git command.'.  It executes the request
and sends the response back as json.

Clearly you can do each via individual ssh commands.  But I've worked in a
few places where ssh connections - even with a control channel - are slow
enough to establish where using emacs is unpleasantly slow.  So, I've found
that this helps speed things up.

I used claude code to do a lot of the programming.  Generally, due to time
constraints w.r.t. my day job & family responsibilities.

Hello,

I would like to submit ekp for NonGNU ELPA.

  Package:    ekp
  Repository: https://github.com/emacs-taf/ekp
  Maintainer: Kinney Zhang <vhkdzszh@gmail.com>
  License:    GPL-3.0-or-later
  Requires:   Emacs 29.1

ekp implements Knuth-Plass optimal line breaking for Emacs buffers.
Paragraphs are split into boxes, a globally optimal break sequence is
chosen, and lines are justified to the pixel.  It supports mixed CJK and
Latin text, kinsoku rules, discretionary hyphenation, and per-region
break policies for URLs, paths and identifiers.

Points the submission guidelines ask about:

- The Lisp implementation lives in lisp/, not in the repository root;
  ekp.el at the root is the entry file and adds that directory itself.
- CHANGELOG.md is the changelog.
- There is no Texinfo manual.
- native/ holds an optional C accelerator that the user builds on
  request with make; the package is fully functional without it.
- dictionaries/ carries 84 hyphenation patterns taken from LibreOffice.
  MANIFEST.tsv pins the upstream commit and records the licence evidence
  for each file; LICENSES.md explains the scheme.
- The repository ships 59 acceptance tests, run with make check.

The package passes package-lint with no issues, checkdoc on every file,
and byte compilation with warnings treated as errors.  It also loads
correctly when installed as a package and loaded from its native-
compiled output, with only the package root on load-path.

For the C-h P description, please use the Commentary of ekp.el: the
README is Markdown, and the Commentary opens with the package summary.

One question: should tests/, scripts/ and benchmarks/ stay in the
package tarball?  They are not needed at runtime, and dictionaries/ is
6 MB on its own.

Regards,
Kinney
